# Docs (documentation update)

Update project documentation in `documentation/` to reflect recent changes.

1. **Scope:** Determine what changed (new API, new feature, config, setup) and which docs are affected.
2. **Locations:** All non-README/SETUP docs go in `documentation/` as markdown. Check `documentation/` and `documentation/build-specs/` for existing files to update.
3. **Actions:**
   - Update existing docs (e.g. API overview, setup steps) with new endpoints, env vars, or behavior.
   - Add new docs if a new feature or module deserves its own page (e.g. `documentation/feature-x.md`).
   - If working from a build spec, update the spec's Status/Updated and any "Documentation" section.
4. **Format:** Use clear headings, code blocks where helpful, and links to code or other docs. Keep prose concise.
